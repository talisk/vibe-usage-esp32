# 智能待办与 LLM 配置使用说明

本功能适用于 Vibe Passport（FoloToy AI Passport）和 Vibe Note（ZECTRIX NOTE4 黑白款）。两者共用待办、语音请求和提醒逻辑，分别使用 LCD 与墨水屏显示。以下为当前实现的操作说明；主机订阅 ASR/LLM 已通过合成输入实测，真机、手机 NFC 与麦克风效果仍需单独验收。

## 首次配置

1. 在概览页长按 OK 进入设置。上下键选择最后一项 **LLM config / 大模型设置**，短按 OK 打开。进入设置页后再长按 OK 可返回概览。
2. 设备尚未联网时，显示第一张 Wi-Fi 二维码。用手机扫码连接屏幕上的 `VibePassport-XXXX` 或 `VibeNote-XXXX` 热点。在此页短按 OK 切换第二张二维码，再扫码打开 `http://192.168.4.1`，选择家庭 Wi-Fi 并保存。热点与配网页临时开放，超时后需要重新进入。
3. 设备连上家庭 Wi-Fi 后，屏幕切换为 LLM 配置二维码。让手机也连接同一 Wi-Fi，再次扫码打开设备当前的 `http://192.168.x.x/?token=…` 地址。设备已经联网时，直接显示这张二维码。
4. 选择 OpenAI、OpenRouter、SiliconFlow 中国站、SiliconFlow 海外站或自定义 Provider。中国站使用 `api.siliconflow.cn`，海外站使用 `api.siliconflow.com`；请选择创建 API Key 的对应站点。预设会自动填写完整 Endpoint、推荐 Model、ASR 识别语言 `zh`，并把上传方式设为 **Auto**；仍可逐项修改。识别语言可填 `zh`、`en`、`zh-CN` 等服务支持的代码，留空则不发送该参数并由服务自动识别。Auto 对 OpenRouter 使用 Base64 JSON，对 OpenAI、SiliconFlow、Codex 中继及其他接口使用 multipart WAV。兼容接口要求不同格式时，可在页面明确选择 multipart 或 Base64。填写两个 API Key 后保存；两个服务使用同一 Key 时，也需在两处分别填写。页面不会读回已保存的 Key；地址未变时留空表示保留，修改地址后留空会在保存时清除该地址对应的旧 Key。也可用对应复选框明确清除。网页中的折叠说明给出了 API 与 Codex 网关配置步骤。
5. 设备短按 OK 关闭 LLM 配置页；配网阶段可长按 OK 返回。临时 LLM 服务在关闭、超时或离开对应网络时停止，下一次进入产生新的访问链接。

支持的协议是 OpenAI Chat Completions JSON，以及 Audio Transcriptions multipart WAV 或 Base64 WAV JSON。仅有文本 Chat 接口的服务不能直接识别麦克风录音，必须另配语音识别接口。URL 填完整路径，例如：

```text
Chat: https://api.openai.com/v1/chat/completions
ASR:  https://api.openai.com/v1/audio/transcriptions
```

模型名称以所选服务实际提供的名称为准。云服务使用校验证书的 HTTPS；局域网服务可配置 `http://192.168.1.10:8000/v1/chat/completions` 这类私有 IPv4 地址。手动配置时需填写完整路径；设备不会跟随重定向。修改 Endpoint 时，确认对应 Key 可以用于目标服务。

配置页面通过局域网 HTTP 传输，持有二维码链接的人可以修改配置，因而请在可信 Wi-Fi 下操作并及时关闭。发起语音命令时，录音发送给配置的 ASR 服务；识别文字和当前待办发送给配置的 Chat 服务。

## 使用 Codex / ChatGPT 订阅

1. 按[中继启动说明](../services/codex_gateway/README.zh_CN.md)，在保持在线的 macOS/Linux 电脑、NAS 或树莓派上启动服务。可运行 `codex login --device-auth` 用授权码完成首次登录；授权码不是设备 API Key，登录后主机仍需持续运行网关。
2. 在设备的 LLM 网页选择 **Codex subscription（实验性主机中继）**，填写电脑的局域网地址，例如 `http://192.168.1.10:8765`，并填入中继专用 Key。
3. 页面自动配置 Chat 和 ASR 的路径及模型别名。勾选启用并保存，回到 TODO 页操作即可。手机、设备和主机需要互通，不能填 `127.0.0.1`。

ASR 通过实验性 Voice 会话转写，LLM 通过 Codex 任务解析。两者可以使用
同一个 ChatGPT 登录，但 Voice 和 Codex 任务各有额度限制。电脑休眠、
退出服务或订阅权限不足时，设备会显示请求失败，保留已有待办。

当前实测是主机上的合成中文录音，并非两块板的麦克风验收。语音路径
会忽略助手回复，只使用最终用户转写；识别不完整时会失败，需要重新说。
详细边界见[订阅接入记录](codex-subscription-feasibility.zh_CN.md)。

## 查看与语音操作

主页面按顺序为 **概览 → Agents → 状态 → TODO List**。上下键切换；Agents 和 TODO List 超过一屏时先翻动列表，到列表边界才切换页面。系统停在配网、授权或错误页时，也可用上下键进入待办页，不要求先绑定 Vibe Usage 账号。

- Passport 每屏显示 3 条，Note 每屏显示 4 条，列表最多 12 条。每条显示顺序编号、完成状态、标题、下一次提醒时间与重复提醒标记。
- 在 TODO List 页长按 OK。看到“正在聆听”后开始说话，松开 OK 发送；最长录音 8 秒，达到上限后自动结束。录音与模型处理期间不切换页面，结果显示在列表顶部。
- 长按后的松开只结束语音，不应触发一次短按返回。Note 的停止信号直接来自按键任务，不需要等待墨水屏刷新完成。
- 普通短按 OK 返回概览；有正在提示的提醒时，短按 OK 停止提示并留在待办页。它不会将该事项标为完成。返回概览后长按 OK，可再次进入设置。
- 长标题会在屏幕上省略显示，保存的原文不因显示省略而被修改。执行完成或删除时可说事项编号，减少同名条目的歧义。

可使用以下语句进行验收：

| 语音示例 | 期望行为 |
| --- | --- |
| “添加一个待办，买牛奶” | 新增一条未完成事项 |
| “两小时后提醒我浇花” | 新增事项，记录两小时后的提醒时间 |
| “每隔三小时提醒我喝水” | 新增事项，带三小时重复间隔 |
| “完成第 2 个待办”或“完成编号 2” | 对模型明确识别出的事项标为完成 |
| “删除编号 3 的待办” | 删除指定事项 |
| “123 已完成” | 将编号 1、2、3 一次性标为完成 |
| “请删除 456” | 按删除前的编号一次性删除 4、5、6 |
| “完成 2、9、3”（没有编号 9） | 忽略 9，仍完成编号 2、3 |
| “今天的天气怎么样” | 不产生明确的待办变更 |

删除事项时，所有目标都按操作前的显示序号匹配；完成删除后，剩余事项按当前顺序重新编号为 1 到 N，新事项使用 N+1。批量请求中的重复或不存在序号会被忽略，不影响其他有效序号；若整批都不存在，则不修改列表并显示失败提示。语音删除会直接执行模型识别出的明确操作，验收时使用测试事项。

## 提醒与持久化

待办及提醒计划保存于设备本地。重启后可再次读取，不依赖 Vibe Usage 账号或云端待办服务。提醒依赖有效时钟；时钟未同步时，先恢复 Wi-Fi 与时间同步，再验收相对时间或重复提醒。

到达提醒时间后，设备按“滴滴滴、停 1 秒、再滴滴滴”的节奏播放六声提示，并转到对应待办所在的列表位置；Passport 同时唤亮屏幕。完成或删除事项后不再继续该事项的提醒。重复提醒显示下一次到期时间，并按保存的间隔继续。

Settings 中的 **提示音** 依次切换静音、25%、50%、75%、100%。非静音档位保存成功后会播放一次试听提示；静音只关闭本地待办提示音，不影响录音或语音请求。音量在重启后保留，旧版本升级后的默认值为 50%。

当前提醒要求设备保持运行供电。本实现没有增加关机唤醒、深睡眠 RTC 闹钟或离线可靠授时机制。尤其 Note 长按 DOWN 关机后，不能期待到点自动开机响铃。验收跨重启行为与长时间提醒时，应分别记录实际电源条件及恢复后的设备时间。

## NFC 配网差异

**Vibe Note：** 固件在临时 Wi-Fi 配网时尝试写入动态 NFC NDEF，屏幕显示“NFC 感应配网”时可用手机贴近 NFC 区域。若屏幕显示“NFC 不可用”，使用二维码完成相同流程。手机是否自动加入 Wi-Fi、是否提示打开浏览器，取决于手机系统对 NDEF Wi-Fi/URI 记录的支持；感应后仍可能需要手动确认热点或再次扫码。请用实际 Android/iPhone 分别验收，不能把标签写入成功当作手机配网成功。

**Vibe Passport：** 板上的 NTAG213 是被动标签，ESP32 没有动态写入通道。第一次需要用支持写入 NFC 标签的手机工具，为标签写入屏幕上的设备热点 Wi-Fi 记录及 `http://192.168.4.1` URI；以后在设备配网热点开启时即可感应。不要把家庭 Wi-Fi 密码写到标签，也不要对标签永久锁定。仅写 URL 的手机通常仍需先手动加入设备热点。设备未进入配网状态时，标签不会替设备开启热点。

两个硬件始终保留二维码路径。NFC 标签只用于配网，不承载 LLM API Key 或临时 LLM 配置 token。硬件差异及标签写入细节见 [NFC 与音频开发文档](smart-todo-hardware.md)。

## 动态标题字库

设置、状态和提示文案提供 English、简体中文、繁體中文、日本語四种语言。TODO 标题另有独立的 16,866 字动态字库，覆盖所锁定 Noto CJK 字体中 GB2312、Big5、Shift-JIS 编码的联合字符及 ASCII。Passport 使用 12px 1bpp 专用字体，避免将三个 UI 字号同时扩成大字库；Note 使用 16px 单色补充字模。

这不是完整 Unicode 字体：罕见扩展汉字、Emoji 等范围不在其中；超出固定基线的全角 `＾`（U+FF3E）和全角重音符号（U+FF40）也明确排除。标题在存储和模型请求中保留 UTF-8 原文，缺少字模仅影响设备显示。生成器会校验锁定的字体哈希与字形边界，不对个别字做居中、缩放或裁切。

```bash
python3 tools/generate_ui_resources.py build/font-input/NotoSansCJKjp-Regular.otf
python3 tools/generate_todo_fonts.py build/font-input/NotoSansCJKjp-Regular.otf
./tools/test-ui-layout.sh
```

## 验收清单与边界

在两块实际设备上分别执行，记录源码版本、固件 SHA256、电源、按钮动作与观察结果；不要记录真实 API Key、原始录音或私人待办。

1. 未配网进入 LLM 设置：第一张二维码加入设备热点，第二张二维码打开配网页，保存家庭 Wi-Fi，手机回到同一 Wi-Fi 后扫描第三张 LAN 配置二维码。
2. 联网直接进入 LLM 设置；分别测试保存、关闭、重新进入、清除 Key、超时，确认旧链接不继续可用。重启后复查设置保留情况。
3. 长按 OK 开始、短语录音松开发送、持续超过 8 秒自动停止、松开后仍停在 TODO 页；处理期间再次按键不会重复创建。
4. 分别新增、完成、删除；建立满 12 条列表，验证每条均可翻到，删除后编号与分页仍正确。
5. 用简体、繁体、日文与 96 字节标题测试显示。Note 进入/退出或切换 QR 时执行完整刷新，观察无残影；Passport 检查圆角黑边、页脚箭头及文字无越界。
6. 短时提醒、重复提醒、到点扬声器、短 OK 停提示、完成/删除停止后续提醒；重启验证持久化。测试断网、无效时钟、服务错误及无效模型响应时已有待办仍保留。
7. Note 实际 NFC 感应，写入失败时二维码回退；Passport 手机首次写入后感应。每种手机单独记录，不合并为笼统“NFC PASS”。

本说明对应的软件路径已经有静态检查、主机字体/画布/二维码检查；它们不能证明麦克风拾音质量、扬声器音量、NFC 天线效果、真实服务鉴权、手机兼容性或电池运行时间。最终交付报告应分别列出 Build、Host tests、CI、Real API、Device、Installer、Power 状态。
